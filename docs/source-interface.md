# 来源接口：配置、发现与材料收件箱

本功能用于日报、周报的材料收集。入口是控制台的「来源」页面（`/sources`）。用户可以按主题联网检索，也可以直接配置来源，或指定一个网站，让系统发现并试读其中的 RSS、Atom 或栏目链接。这个阶段不调用模型，不判断新闻重要性，不自动发布报告。

## 主题联网检索

在「联网检索」填写主题、检索词和起止日期，保存方案后手动运行。不同检索词分别请求搜索服务，结果进入同一个材料收件箱；无需先登记所有媒体。可直接打开 `/sources?view=search`。[上海 ESG 与绿色金融检索样例](../examples/search/shanghai-esg-green-finance.json) 固定了 **2026-09-20 至 2026-10-19** 的窗口和 8 条检索词；名称中的“近 30 天”指这个冻结窗口，不会随日期自动滚动，使用时须调整日期及包含年月的检索词。[较早的检索样例](../examples/sources/shanghai-web-search.json) 保留作历史参考。

先在设置页配置搜索服务：

本机没有搜索服务时，可按 [SearXNG 部署说明](../deploy/searxng/README.md) 启动官方容器。当前机器如使用虚拟 IP DNS，可在服务设置将「原文地址解析」改为 Cloudflare 加密 DNS；默认仍使用系统解析，所有连接仍需通过公网地址检查。

| 服务 | 配置 | 日期与调用边界 |
|---|---|---|
| SearXNG | `SEARXNG_URL`，填写实例基地址，实例必须启用 JSON 输出 | 每个词只取第一页；近期窗口发送能涵盖范围的月／年提示，是否支持由上游决定，精确起止日期仍由原文核验 |

SearXNG 是唯一的搜索服务（百度独立搜索已移除）；中文覆盖取决于 SearXNG 实例启用的搜索引擎。此前为百度保存的方案仍可查看材料和重核日期，但不能再保存或运行，须改为 SearXNG 后保存。旧 `settings.json` 中的 `BAIDU_SEARCH_API_KEY`、`ISBE_SEARCH_DAILY_LIMIT` 读取时忽略，下次保存设置时删除；数据库表 `search_daily_usage` 保留但不再写入。

保存服务配置不发送请求。缺少服务时仍可保存方案，不能执行检索。每个方案 1–8 条不同检索词，每条最多 200 字，每词最多接收 20 条结果；达到限制会提示可能还有更多结果。`language` 为 `zh-CN` 或 `en`，中文、英文关键词可放在同一方案中；它不保证搜索引擎只返回某一种语言。

搜索请求不自动重试。搜索任务重启后标为中断，不重新发起状态未知的外部请求。

材料保留标题、原文网址、摘要、搜索服务、检索词和搜索返回日期。搜索返回日期是线索，不写入原文发布日期。每次运行最多核验 20 个不同网页的日期，剩余材料保持未核验；读取失败、没有明确日期、多个日期冲突的材料都保留。日期状态分为「符合范围／范围外／日期不明／日期冲突」，收件箱可按状态筛选；范围外的记录不会被删除。同一方案的相同网址合并展示，保留各次命中记录；不同媒体的不同网址继续分别保留，不以模型相似度自动合并。

原文日期核验只读公开 HTTP(S) 网页的明确日期信息，不从网址、抓取时刻或 HTTP 修改时间推断发布日期。搜索服务请求最多 30 秒、2 MiB，不跟随重定向；原文核验最多 8 秒、1 MiB，最多 3 次重定向，每一跳重新检查公开地址。日期符合范围不意味着内容已人工核验、事件发生于该范围内，或可直接收入报告。检索内容可能包含企业宣传、媒体转载和社区观点，应按原文标注发布者及发言者。

原文日期读取支持网页明确声明的字符编码，包括 GB2312、GBK、GB18030、Big5 等：优先读取响应头中的 charset，其次读取 HTML 头部声明；没有声明时按 UTF-8 处理，不猜测编码。未知编码或字节与声明不符时记录读取失败，不用替换字符掩盖解码错误。这项扩展仅用于原文日期核验，固定 RSS／栏目采集仍沿用原有读取限制。

除明确的日期元数据外，日期规则补充了四类文章头部结构：中新网上海（`www.sh.chinanews.com.cn`）、21 世纪经济报道移动站（`m.21jingji.com`）、东方财富财经（`finance.eastmoney.com`）及界面新闻（`www.jiemian.com`、`m.jiemian.com`）。规则限定到这些站点的文章路径和标题附近日期区域，不扫描全文中的任意日期，也不把导航、推荐文章、活动时间或“更新”日期当作发布时间。头部日期与其他明确发布时间不一致时仍保留冲突，不凭规则优先级选择一个日期。界面电脑版忽略空白容器，要求完整主文区域唯一；移动版仅读取文章头部明确的 `data-article-publish-time`，按原站脚本确认的 Unix 秒转换为 UTC，并保留原始秒值。原站显示使用浏览器本地时区，因此不擅自添加固定的 `+08:00`。

另外补充了第一财经快讯、中国公益网 ESG 文章、同花顺债券文章和新民晚报电子报：第一财经组合同一快讯主文的日期与段首时刻；中国公益网、同花顺只读取标题信息行。新民晚报使用同一篇正文对应的报纸刊期，证据字段明确标为 `edition_date`，只保存日期，不补写发表时刻；页顶当天日期不参与归类。各站规则均有固定 HTML 样例及无标题、重复主文、推荐区域和正文事件日期的反例。

页面声明 ByteDance、微博的发布／更新时间元数据时也会读取；二者相互冲突时保留冲突，更新时间不当作发布日期。

### 来源能力描述

`isbe/search/capabilities.py` 逐项记录通过搜索服务（`searxng`）和各类固定来源（`rss`、`page`）运行时，研究范围中的约束能否执行。每项状态取以下三者之一：

- **支持**：运行时确实执行。
- **不支持**：请求无法表达。应写进检索词，或在结果上另行核对。
- **未知**：请求可能带上了该条件，但没有核实来源是否执行。未知不当作支持。

每项都写明依据（ISBE 的请求代码、本文记录的边界，或尚未核实），以及请求里实际发送的字段。描述不读取服务设置，只出现设置名，不含密钥、地址或本机路径；是否已配置仍由服务可用性接口给出。能力描述不评价检索质量或来源可信度：字段存在不代表结果相关、完整或可靠。

| 约束 | SearXNG | RSS／栏目 |
|---|---|---|
| 检索词 | 支持 | 不支持（不接受检索词） |
| 精确短语、OR、排除、`site:`、`intitle:` | 未知（原样传给上游） | 不支持 |
| 机构、地域 | 不支持 | 不支持 |
| 语言 | 未知（发送 `language`，结果语言不核对） | 不支持 |
| 发布时间窗口 | 不支持（只有月／年近期提示） | 不支持 |
| 翻页 | 不支持（只取第一页） | 不支持 |
| 条数上限 | 支持（1–20） | 支持（1–200） |
| 总数估计 | 不支持 | 不支持 |
| 结果日期即发布日期 | 不支持（只作线索，需重核） | RSS 支持（订阅源自报，未对原文核对）；栏目不支持 |

`for_plan`、`for_source` 把描述与检索方案或来源的配置版本（revision）绑定；仍为百度保存的方案没有描述，查询时与保存、运行一样返回 400。`route` 把研究范围要求的约束分为三组：请求执行的、需在结果上核对的，以及其中能力未知的。[输入样例](../examples/search/capabilities.json) 由代码生成，测试保持两者一致；样例按研究范围约定的地域、语言和发布时间窗口给出各来源的分流结果。描述变化时同时更新版本号 `REVISION` 和样例。

**选型说明**：目前只接入可自建的 SearXNG；Tavily、Exa 等付费接口没有做过对比评测，所以 SearXNG 不是评测胜出的结果。百度此前只有适配和模拟测试，没有真实调用记录，已移除。

### 检索语法与约束

检索词按 Google 学术的规则解析，`isbe/search/query.py` 在保存检索方案时检查每一条，写错的语法当场报错并指出问题；生成请求不联网，也不调用 LLM。

| 写法 | 含义 |
|---|---|
| `上海 ESG` | 空格分隔的词必须全部出现 |
| `ESG OR 可持续` | 大写 `OR` 连接两个词或短语，任一出现即可；小写 `or` 只是普通单词 |
| `"绿色金融"` | 精确短语；中文引号 “…” 会转成英文引号，短语内的多余空格合并 |
| `-招聘`、`-"job ad"` | 排除 |
| `site:gov.cn` | 限定网站，只接受域名 |
| `intitle:转型`、`intitle:"transition plan"` | 限定标题 |

会被拒绝的写法：引号未闭合或为空；`OR` 在开头、结尾、连写，或后面接排除词、`site:`；单独的 `-`；`site:`、`intitle:` 后没有内容；`site:` 后跟短语；只有排除词或 `site:`、没有可检索的词；`author:`、`source:`（Google 学术字段，网页搜索无从匹配，请把姓名或刊名加引号写进检索词）。不做自动扩词、翻译或改写。

**实际发送的内容**：检索方案可填可选的“地域”和“机构”（各 60 字以内，不含引号）。每条检索词发送的是整理后的原文（空白合并、引号统一），再把地域、机构各作为一个引号词组追加在后面；检索词里已经包含同样文字时（不分大小写）不重复追加。`search_requests.query` 仍保存用户写的那一行，每条检索记录的 `sent` 是实际发送的文本。没有填写地域和机构的方案，保存格式与此前相同，旧方案无需迁移。

**留待结果核对的约束**：搜索服务没有地域、机构参数，也没有核实它是否执行短语、OR、排除、`site:`、`intitle:`、语言和发布日期窗口。因此每条检索词都会按[来源能力描述](#来源能力描述)分出“请求执行的”“需在结果上核对的”“其中能力未知的”三组，记录在该条的 `constraints`；整次运行的 `unexecuted` 是各条需核对约束的并集，控制台的检索记录里列出“搜索服务未按这些条件过滤，请在结果中核对”。约束不会被静默丢弃；是否满足仍由人在结果中判断，程序只核对原文发布日期。

离线样例见[能力样例](../examples/search/capabilities.json)的最后一条：`上海 "绿色金融" ESG OR 可持续 -招聘`，地域“上海”、机构“上海证券交易所”，实际发送 `上海 "绿色金融" ESG OR 可持续 -招聘 "上海证券交易所"`（地域已在检索词中，不重复追加）。

### 已收录材料的日期重核

方案卡片的「查看材料」只打开该方案的材料，显示当前方案窗口。链接可保存方案和日期筛选，例如 `/sources?view=materials&source=search%3Ashanghai-esg-live-20261018&date_status=in_range`；刷新或浏览器后退会恢复对应筛选。保存方案的新起止日期时，已有明确发布日期按当前窗口重新归为范围内或范围外，不修改发布日期，也不为此重新访问网站；未知日期和冲突状态继续保留。

点击「重新核对日期」只读取该保存方案已有材料的原文，不调用搜索服务。每批最多 20 条，正常完成或部分完成后可点击「继续核对余下条目」；任务失败或中断时使用「重新核对本批」，从本批原游标重试，避免跳过尚未处理的材料。每次操作由用户明确发起，提交结果未知时不自动重发；采集与日期重核沿用同一个执行锁。

有采集或日期核对任务正在运行时，保存检索方案会返回冲突，须等任务结束后再保存。保存与任务启动在数据库事务内互斥，防止旧任务把材料重新写回旧日期窗口。

读取失败时保留此前已有的发布日期或冲突证据，单独记录最新核对失败；没有既有日期的材料继续显示未知。保留旧发布日期时，界面给出简短提示；原始日期证据与最新核对结果分别留存。重核不改变首次收录时间、最近搜索命中时间或原有搜索服务与检索词记录，失败也不会把旧材料置顶。

```text
isbe --data data sources search-save examples/search/shanghai-esg-green-finance.json
isbe --data data sources search-list
isbe --data data sources search shanghai-esg-live-20261018
# 修改已有方案须携带 search-list 返回的 revision
isbe --data data sources search-save edited-search.json --revision 1
# 核对第一批；后续批次使用上次完成任务返回的 next_cursor
isbe --data data sources recheck shanghai-esg-live-20261018
isbe --data data sources recheck shanghai-esg-live-20261018 --after <next_cursor>
```

搜索接口同样仅供本机或共享模式管理员使用，沿用 CSRF：

- `GET /api/sources/search`：方案与 SearXNG 配置状态。
- `POST /api/sources/search`：`{config, revision?}`；新增不传版本，修改携带当前版本。
- `POST /api/sources/search/run`：`{config, request_id}`；配置必须与已保存方案一致，每个请求 ID 只执行一次。
- `POST /api/sources/search/{id}/recheck`：`{request_id, after?}`；按保存方案核对最多 20 条已有材料。正常完成或部分完成时以 `stats.next_cursor` 继续；失败或中断时用原 `stats.after` 和新的请求 ID 重试本批，首批不传 `after`。任务记录包含本批已核对数、余下条数及日期状态统计。
- `GET /api/sources/materials?source=search:<id>&date_status=unknown&offset=0`：与固定来源共用材料箱，筛选可省略。任务状态沿用 `/api/sources/jobs`。

当前手动运行，不创建定时任务；不接入 Google／Bing 已退役或限存量客户的旧 API，也不宣称已有知乎直接接口。检索方案可使用 `site:zhihu.com` 等关键词，但是否支持该语法取决于实际搜索服务。接口参考：[SearXNG](https://docs.searxng.org/dev/search_api.html)。

## 使用流程

来源、材料和采集记录分开管理。默认打开来源管理台，显示全库来源概况；搜索与筛选只影响下方结果，不改变全库统计。

1. **定位一批来源**：通过名称／地址／专题文字搜索，按网站、专题、启用状态或最近读取结果筛选。服务器每次只返回 50 个来源，分页后再加载下一批；网站和专题可输入查找，不需要遍历长列表。
2. **批量调整**：勾选当前页的一批来源后，统一启用或停用。切换筛选或分页会清空选择，避免操作已经看不到的来源。每个来源都携带读取时的版本号，任意一个被其他页面修改，整批拒绝，保留原设置；刷新核对后再操作。
3. **按需查看详情**：在行内打开配置，或查看该来源的材料。新增、发现、导入属于单独展开的操作，不占用日常巡检界面。材料页既可查看全部记录，也可只看选定来源；采集记录显示最近任务及新增、更新、失败情况。

具体来源的配置规则：

1. **直接配置**：填来源名称、所属专题、RSS／网页类型和地址，保存后点击试采集。网页来源可填写「链接包含文字」筛选文章路径；它是地址中的字面文字，不是正则表达式。留空时只提取带明确日期路径的文章链接。
2. **自动发现**：填写具体网站首页或栏目页、所属专题。默认勾选「试读成功后自动启用」。发现限定为该地址的协议、主机、端口一致的来源，每次最多试读 8 个候选；达到上限会提示。只有至少读出一条有效线索的新来源才启用。空来源或失败来源保留为停用候选；用户已停用的来源不会被重新启用。
3. **核验材料**：收件箱展示来源、标题、原文链接、可用摘要、发布日期、来源更新时间、首次发现时间和版本数。没有发布日期就显示未知，发现时间不充当发布日期。重复采集不增加重复材料；相同来源、相同链接的标题或摘要发生变化时保留旧版本。不同来源的同一链接分别保留，方便对照。
4. **调整配置**：停用后保留已收集材料，仍可手动试采。修改采用版本检查，防止两次打开的页面互相覆盖。已有材料的来源如需变更地址、类型或专题，应新增来源，保留原有归属。

## 配置文件与命令

页面支持 JSON 导入、导出，命令行还支持 YAML。导入是一次性的新增操作，不持续同步文件；重复 ID 会让整批导入失败，不覆盖现有配置。

```yaml
sources:
  - id: sh-finance-news
    name: 上海金融·工作动态
    topic: 上海 ESG 与绿色金融
    kind: page
    url: https://jrj.sh.gov.cn/ZXYW178/index.html
    enabled: true
    link_pattern: /ZXYW178/
    max_items: 100
```

```text
isbe --data data sources import sources.yaml
isbe --data data sources list
isbe --data data sources export
isbe --data data sources discover https://jrj.sh.gov.cn/ZXYW178/index.html --topic "上海 ESG 与绿色金融"
isbe --data data sources collect
isbe --data data sources collect sh-finance-news
```

无 ID 的 `sources collect` 采集所有启用来源；显式给 ID 可以试采停用来源。发现加 `--candidates-only` 可保持候选停用。命令等待采集完成并输出结果；部分或全部失败时返回非零状态。网页中的采集在后台运行，关闭页面不会自动重新提交。

## API 与数据

- `GET /api/sources?q=&site=&topic=&status=&offset=0`：来源分页，每页 50 条。`q` 是字面子串搜索；`site` 是主机及可选端口，`topic` 精确匹配，`status` 可为空、`enabled`、`disabled`、`failed`、`empty`、`never`。响应 `total` 是筛选结果数，`summary` 与网站／专题 `facets` 是全库统计。
- `GET /api/sources/config/{id}`：独立读取配置；`POST /api/sources`：新增；`PUT /api/sources/{id}`：带 `revision` 修改。
- `POST /api/sources/batch`：`{ "sources": [{ "id": "source-id", "revision": "1" }], "enabled": false }`，一次 1–50 个来源，原子地更新启用状态；冲突不部分执行。
- `GET /api/sources/export`、`POST /api/sources/import`：配置导出、整批新增。
- `POST /api/sources/discover`：`url`、`topic`、`auto_enable`、`request_id`。
- `POST /api/sources/{id}/collect`：`request_id`。
- `GET /api/sources/jobs`：最近 20 个任务；相同请求 ID 不重复执行不同操作。
- `GET /api/sources/materials?source=<id>&offset=0`：材料分页，每页 50 条；每条附文章身份 `identity` 与重复数 `duplicates`，`counts` 分列命中、材料、版本与文章数。`GET /api/sources/materials/{id}/timeline`：该文章的全部出现记录，最新在前（见下文“重复材料与时间线”）。

请求沿用登录、工作区和 CSRF 机制。共享模式仅管理员可配置与访问这些自定义出站来源；普通用户无此权限。发现不会跨主机自动扩张，不跟随重定向；需要跳转的来源应配置最终地址。固定来源请求最多 15 秒、2 MiB，每个来源每次最多 200 条，采集与报告任务共用执行锁。来源 URL 中的凭据和 fragment 不接受。

SQLite migration 007 新增独立来源、抓取响应、材料版本和任务表，不改写已有报告。采集保存响应原件和摘要版本用于后续追溯；当前界面展示最新摘要及版本数。备份整个数据目录即可保留这些记录。恢复旧版本程序前应使用升级前的数据库备份。

## 当前边界

固定来源完成配置 → 发现／试读 → 启用 → 材料收件箱；主题检索完成方案配置 → 请求搜索服务 → 有界日期核验 → 材料收件箱，已收录材料可再分批核对日期，并生成材料汇编。RSS／Atom 读取订阅内容，网页来源读取静态 HTML 栏目链接；固定 RSS／栏目读取器未接入本次非 UTF-8 编码扩展。原文日期核验支持上述明确编码声明及八家发布方的九种文章头部结构，但不保证其他站点结构、未声明编码或依赖 JavaScript 的日期可读取。

媒体正文已有站点适配和持久缓存；编辑稿可引用保存的原文，按议题发布行业周报。**通用 PDF 获取与解析、需执行 JavaScript 的网页、自动定时任务、网页选稿编辑和自动编写下一期尚未接入该流程**。HTML 链接不从地址猜测发布日期。所有命中先保留，不声称已做主题相关性筛选。

检索结果只是候选，可能包含行情、聚合页、无关报道和全国背景；日期归为“范围内”也不等于相关或可入选。检索与日期归类不使用 LLM 判断或剔除内容。日期待核对既可能是页面没有当前规则可识别的明确日期，也可能是读取失败，不能据此断言原网页没有日期。

固定来源的「启用」表示纳入下一次批量采集，不表示已经设置定时采集。配置可用于现有外部调度方式；本功能不会自行创建系统计划任务。后续可扩充翻页、更多站点正文适配和日报／周报的新增／更新对照。

管理台支持按网站与专题定位已有来源。来源当前仍归属于一个专题；它不是多标签订阅体系，已有材料的专题不能通过批量操作迁移。批量操作只作用于明确勾选的当前页，不隐式选择所有搜索结果。来源管理分页也不等于网站文章翻页采集。页面只展示最多 20 个匹配的网站／专题提示；分页管理不代表已具备千站并发抓取、限流调度或持续运行能力。

## 示例来源配置

[真实来源样例](../examples/sources/shanghai-esg-green-finance.json)包含 10 个已启用的来源，来自 7 个机构，可直接导入：

| 机构 | 内容范围 |
|---|---|
| 上海环境能源交易所 | 全国碳政策、上海碳市场制度；含历史政策背景 |
| 浦发银行 | 集团 ESG 实践、绿色金融、中英年度报告入口；业务包含上海以外地区 |
| 上海交大高金 | 上海 ESG 研究、责任投资与可持续发展活动 |
| 中央财大绿金院 | 绿色金融、保险 ESG、转型金融研究；全国背景 |
| 第一财经·一财 ESG | 上海活动、企业 ESG 案例及访谈；含全国企业 |
| 上海证券交易所 | 可持续发展报告编制指南、披露实践案例；参考文档集合 |
| 上海市绿色建筑协会 | 上海低碳建筑、照明、行业标准与活动 |

导入只保存配置，采集仍需手动执行。上交所两个入口是参考资料，案例集路径对应采集时的版本，新版更换目录时须更新配置。网页栏目只读取当前静态首屏，不支持加载更多或历史回填。

使用这些来源时需注意：页面日期未提取时保留未知；地址中的日期与正文日期可能不同，不能用地址猜发布日期；收录时间不表示新闻发生在当天；全国研究和集团业务不能直接作为上海成效；历史资料不能当作本周新增事件。部分网站有连接或访问限制、或依赖 JavaScript，未列入示例；UNEP FI 的中国分类 RSS 实际混入全站内容，也未按“中国来源”接入。

## 媒体材料接入周报

在检索方案卡片或该方案的材料收件箱点击「生成材料汇编」，选择现有报告专题或以该检索方案建立独立报告专题，再选择已结束的星期日。默认选择最近一个已结束的完整周；当天为星期日时仍选择前一周。生成后点击「打开材料汇编」即可在已有周报阅读器中阅读、下载 Markdown 或打印。生成不启动搜索，不调用模型，不执行旧论文流程的筛选与评分。

周报按周一至周日划分，使用已核对的发布日期：带时区的时间换算到北京时间，未注明时区的时间沿用来源记录的日历日期。原检索方案中的「范围内」只代表检索窗口，不能直接当作本周。正文包括本周报道、周前回看和周后新增，日期待核对、日期冲突及检索窗口外的材料保留在折叠附录。每条显示日期、「来源｜标题」原文链接与明确标注的检索摘要。摘要来自搜索结果，尚未形成全文提取的主体、对象或事件时间结构化记录；发布机构也不自动视为事件执行主体。

同一主题同一周再次生成时另存新版本（例如 `2026-W42-media-v2`），原周报和研究报告均不覆盖。每份报告旁保存 `.sources.json`，包含当时的方案、全部材料内容、日期证据及首次／最近收录时间；后续重核日期不会反向改写已生成的报告。书架、历史期刊和首页显示材料数量，不混作论文数。

命令行也可使用：

```text
isbe --data data media-weekly shanghai-esg-live-20261018 --topic shanghai-esg-green-finance --week-end 2026-10-18
```

接口：`POST /api/sources/search/{id}/weekly`，请求体为 `{"topic_id":"shanghai-esg-green-finance","week_end":"2026-10-18"}`。沿用来源管理的管理员、工作区、Host、CSRF 和 JSON 检查，与采集／报告任务共用执行锁；本地渲染完成后返回报告地址与各分区数量。重复请求保存为独立版本，不视为幂等覆盖。

该入口生成的是完整候选材料的汇编，未加入自动选稿、跨媒体事件合并、全文提炼或模型简评。编辑稿发布使用独立的 `media-briefing` 命令，按议题组织事件进展、背景与后续日程，见 [行业周报使用方式](research.md#媒体材料与行业周报)。引用位置检查不等于人工语义核验。

### 原文展开与正文缓存

材料汇编和行业稿中的“展开原文”共用受控读取路径。首次成功解析的正文保存到 SQLite `article_text`（migration 010），重复阅读使用已保存正文；网络不可达、解析未支持及缓存失败分别提示。缓存保存的是解析段落，不是原始 HTML 字节，也尚无原网页修订版重抓取功能。站点适配只覆盖已列出的网站，不代表所有媒体网站均受支持。


## 重复材料与时间线

同一篇文章可能被多个检索方案、同一方案的多次运行或固定来源重复发现，地址也常带不同的跟踪参数。存储时不合并任何记录：每份材料保留自己的命中、查询、排名、原始响应和版本。读取时按文章身份（`isbe/sources/identity.py`）归组，在材料收件箱中标出“另有 N 处出现”，并可展开时间线：逐条列出每次检索命中（运行时间、方案、检索词、排名）和固定来源的每个版本（采集时间、来源、当时标题），最新在前。

文章身份按以下顺序认定：

| 顺序 | 依据 | 示例 |
|---|---|---|
| 1 | 地址中的 DOI：`doi.org` 链接、`/doi/…`、`/article/10.xxxx/…` 等位置或 `doi=` 参数，统一小写 | `https://doi.org/10.1016/J.X` 与 `https://publisher.example/doi/abs/10.1016/j.x` 为同一篇 |
| 2 | 已列出网站的站内文章编号：微信公众号文章的 `__biz`、`mid`、`idx`；界面新闻电脑版与移动版的 `/article/<编号>.html` | `sn`、`chksm`、`scene` 不同的同一条公众号文章为同一篇；同一消息的另一条 `idx` 不是 |
| 3 | 去掉不影响文章的部分后的链接：http 与 https、主机大小写、开头的 `www.`、默认端口、`#` 片段、末尾斜杠、参数顺序，以及跟踪参数 `utm_*`、`spm`、`from`、`isappinstalled`、`fbclid`、`gclid`、`yclid`、`dclid`、`msclkid`、`mc_cid`、`mc_eid`、`igshid`、`share_token` | `https://www.example.org/n?id=1&utm_source=rss` 与 `https://example.org/n?id=1` 为同一篇；`id=2` 不是 |

不作为同一篇的情况：标题相同但身份不同的材料（不比较标题）；转载到其他地址的文章（既不并入原文，也不断言两者独立）；未列出的参数（保留在链接中，宁可漏归组也不错归组）。不做模糊或语义合并。

材料列表的 `counts` 分列四个数：命中数（检索结果出现次数）、材料数（独立记录）、版本数（固定来源每个内容版本各计一次，检索材料计一次）与文章数（不同身份）。同一文章的多次命中或多份材料不代表多个独立来源。重复运行同一方案只增加命中，不增加材料。归组在读取时计算，没有新增迁移，已有数据无需转换。
